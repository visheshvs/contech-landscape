# Turn a static contech map into a living directory

The ConTech Landscape site should copy the proven CNCF Landscape pattern stack: a category-grouped logo or card wall, faceted filters with counts, a deep-linkable company detail drawer, URL-encoded filter state, and open CSV/JSON export. It should then add the views no contech map offers today: a **category x project-phase heatmap**, a **category x customer-type heatmap**, an **UpSet plot of category overlaps**, a **phase swimlane** that separates end-to-end platforms from point solutions, and a **"new this week" changelog** driven by `date_added`. This matters because contech landscapes from Cemex Ventures, Nymbl, Zacua/Leonard and CB Insights are almost all static images, PDFs or paywalled collections. None of them can be searched, filtered by buyer type or lifecycle phase, or kept fresh weekly. At about 50 companies, growing to several hundred or a couple of thousand, everything can run in the browser from one JSON file with no backend. The design rule that matters most is that the data is **multi-label**: a company in two categories counts twice in any treemap, sunburst or Sankey. That pushes the design toward matrix and unit charts, where each company is one mark. The stack can stay a plain `index.html` with small CDN libraries plus a GitHub Actions build step. Astro becomes worthwhile once per-company pages, OG images and RSS are wanted.

## CNCF's landscape sets the pattern; contech has no interactive equivalent

The reference implementation is the CNCF Landscape, now built with **landscape2**, a Rust CLI that generates a static single-page site from YAML data and SVG logos and can be hosted on GitHub Pages ([landscape2](https://github.com/cncf/landscape2)). Its feature set is a good checklist for this site. It has embeddable views of one or more categories with generated embed code, a kiosk/mobile single-item page at `kiosk.html?item=<id>`, a JSON API plus `items.csv` and `projects.md` exports, a downloadable PNG/PDF render of the whole landscape, and `/guide` and `/stats` routes ([landscape2 README](https://raw.githubusercontent.com/cncf/landscape2/main/README.md)). It also has an experimental "overlay" mode that applies alternative data to a deployed site through query parameters, which can be used to preview pull requests ([landscape2 README](https://raw.githubusercontent.com/cncf/landscape2/main/README.md)). The same generator powers the LF AI, CD Foundation and FinOps landscapes ([lfai issue](https://www.github.com/lfai/lfai-landscape/issues/678); [FinOps landscape](https://github.com/finopsfoundation/finops-landscape/blob/HEAD/README.md)). The CNCF also takes new entries through pull requests, with deploy previews ([Netlify case study](https://www.netlify.com/blog/2020/06/04/how-cncf-enables-community-sourced-ecosystem-map-with-netlify-deploy-previews)). The MAD Landscape uses a "dual format": a static PDF map and essay for social sharing, plus a separate "interactive version (searchable, with data cards)" ([FirstMark](https://firstmark.com/story/bubble-build-the-2025-mad-machine-learning-ai-data-landscape/)). MAD's growth from **1,416 logos in 2023 to 2,011 in 2024** shows why a pure logo wall stops being readable at scale ([MAD 2024](https://mattturck.com/mad2024/)).

Contech is a different story. Cemex Ventures publishes an annual Top 50 list and a 2026 Construction Cleantech Map as reports ([Cemex Ventures](https://www.cemexventures.com/?p=112200); [Cemex Cleantech Map](https://www.cemexventures.com/?p=113177)). Zacua and Leonard map **250+ LatAm startups in a PDF** ([Leonard PDF](https://leonard.vinci.com/wp-content/uploads/2026/06/LatAm-Report-Construction-Tech-opportunity__Final-ENG.pdf)). CB Insights' map of **100+ startups across 13 categories** is editable only inside a paid collection ([CB Insights](https://www.cbinsights.com/research/construction-tech-startups-market-map-expert-intelligence/)). Nymbl's built-environment report covers 2,100+ companies as chart-style content, not as a browsable directory ([Nymbl report](https://nymbl-report.pages.dev/built-environment-2026/)). No interactive, filterable contech landscape was found. One caveat: several of these sites were blocked during research, so an interactive layer behind a gate can't be ruled out. Even so, the opening is clear. A free, weekly-updated directory that filters by **customer type and project phase**, the dimensions AECO buyers actually think in, would do something VC market maps do not.

Cemex's startup-competition verticals, such as Preconstruction Tech and Jobsite Productivity, are a useful cross-check for the site's own category taxonomy ([Cemex Ventures](https://www.cemexventures.com/?p=113325)).

## Seven features turn the CSV into a usable directory

The core experience should be a **category-grouped wall that toggles between logos, cards and a table**. At 50 companies, cards with a one-line description add more value than bare logos. The table view suits analysts who want to sort by funding or HQ. Next to it sits a **faceted filter rail** for category, subcategory, customer type, project phase, funding stage and HQ region. Each option shows a live count, and text search sits on top. The whole filter state is written to `URLSearchParams` with `history.replaceState`, so any view ("GC-facing preconstruction tools in Europe") becomes a shareable link. Clicking a company opens a **detail drawer with its own deep link** (`?company=slug`), showing the description, all tags, funding, HQ, website and LinkedIn, and the date added. This is the same idea as landscape2's kiosk item URLs ([landscape2 README](https://raw.githubusercontent.com/cncf/landscape2/main/README.md)).

The weekly cadence should be visible on the site, because it is the main advantage over annual maps. A **"New this week" badge and sort**, a changelog page, and an RSS feed can all come from `date_added` or from diffing the data file against the previous commit. **Open data** should be one click away: links to the raw CSV/JSON, plus a "download filtered results as CSV" button. An **embed mode** (`?embed=1&category=X`) lets newsletters and blogs show one category, which mirrors landscape2's `/embed-setup` ([landscape2 README](https://raw.githubusercontent.com/cncf/landscape2/main/README.md)). A **submission flow** can use a GitHub issue form or a PR against the CSV, as the CNCF does, with a Tally or Google Form for people who don't use GitHub. Finally, a **static PNG export of the map** gives the site its LinkedIn-friendly "dual format", which is how most contech maps spread today. On mobile, the filters should collapse into a bottom sheet and the logo wall should become a single-column card list.

## Matrix and unit charts beat treemaps for multi-label data

The FT Visual Vocabulary's advice applies here: pick the relationship you want to show first (ranking, distribution, part-to-whole, spatial, flow, change over time), then pick the chart ([FT chart-doctor](https://github.com/Financial-Times/chart-doctor/blob/main/visual-vocabulary/README.md)). For a multi-label dataset of 50 to 500 rows, that gives a ranked menu:

| Visualization | Question it answers | Fit / caveat |
|---|---|---|
| Category > subcategory market map | Who plays in each space? | Industry standard. Mark repeats, or use a primary category |
| Heatmap: category x phase (5 cols) | Where on the project lifecycle is coverage thick or thin? | Best single chart for this data. Cells mean "tagged with both" |
| Heatmap: category x customer type | Which buyers (GC, owner, sub, designer) are underserved? | Clicking a cell filters the directory |
| UpSet plot of category intersections | Which category combinations are common? | The honest overlap view. Show the top 15-20 and add an explainer |
| Phase swimlane | End-to-end platforms vs point solutions | Non-contiguous phases need dots, not bars |
| Funding beeswarm (log scale, by round) | How big are rounds; who are the outliers? | Funding text needs parsing. Keep an "undisclosed" group |
| HQ dot map + country bar chart | Where are companies based? | A ranked bar chart is often clearer than a choropleth |
| Cumulative growth line + weekly changelog | How fast is the directory growing? | Label it "added to directory", not "founded" |
| Sankey, treemap, sunburst, chord | Flows and part-to-whole | Double-counts multi-label data. Use only with primary-category sizing |

UpSet is the strongest evidence-backed choice for showing overlap. It displays set intersections as a sortable matrix with aligned bars, scales to roughly **20-30 sets**, works better than Venn diagrams beyond a few sets, and won the InfoVis 10-year Test of Time award in 2024 ([Wikipedia](https://en.wikipedia.org/wiki/UpSet_plot); [Lex et al. 2014](https://vdl.sci.utah.edu/publications/2014_infovis_upset/)). Beeswarms keep each company visible as a dot while still showing the shape of the distribution, which suits funding at this scale ([Flourish](https://flourish.studio/blog/what-is-a-beeswarm-plot/)). ApexCharts' startup-funding unit chart shows the animated version: 220 startups regroup between stage and sector clusters, with dots sized by capital raised. It is a premium chart type, though, and shows a watermark without a license ([ApexCharts](https://apexcharts.com/javascript-chart-demos/unit-charts/startup-funding)). The D3 gallery has reference code for treemaps, sunbursts, Sankeys and chords if decorative overviews are wanted later ([D3 gallery](https://observablehq.com/@d3/gallery)).

Every chart should **read from and write to the same filter state** as the directory. Clicking a heatmap cell or an UpSet bar filters the list, and filtering the list redraws the charts. This is linked brushing, a form of crossfiltering ([Observable blog](https://observablehq.com/blog/linked-brushing)). Mosaic and Vega-Lite have it built in ([Mosaic crossfilter](https://idl.uw.edu/mosaic/examples/crossfilter.html)). At a few hundred rows, though, plain JavaScript state plus re-rendering is instant and simpler. Observable Plot's brush support was still in development in PR #1653 ([PR #1653](https://github.com/observablehq/plot/pull/1653)), and it was not confirmed whether that PR has since merged.

Accessibility should follow Datawrapper's practice: colorblind-safe palettes, automatic contrast, written alt descriptions, a "get the data" link, and keyboard-reachable marks ([Datawrapper](https://www.datawrapper.de/docs/how-we-make-sure-our-charts-maps-and-tables-are-accessible); [keyboard navigation](https://www.datawrapper.de/blog/keyboard-navigation-dynamic-font-scaling)). The Chartability fast pass is a quick audit method ([EU guide](https://data.europa.eu/apps/data-visualisation-guide/fast-pass-accessibility-audit-with-chartability)). Heatmaps have an advantage here: they can be marked up as real HTML tables, which are accessible by default, and they can be transposed on phones so the 5 phase columns fit across the screen. Hover tooltips should be replaced by tap-to-select plus a details panel, and chord, Sankey and network views should fall back to bar charts on small screens.

## A no-build page with small libraries scales to 2,000 companies

The data is small. ItemsJS handles faceted search with counts over JSON datasets "up to 100K items" and ships CDN builds ([ItemsJS](https://cdn.jsdelivr.net/npm/itemsjs@2.4.4/README.md)). Pairing it with MiniSearch for typo-tolerant full-text search is a documented pattern ([ItemsJS + MiniSearch](https://github.com/stereobooster/itemsjs/blob/HEAD/docs/minisearch-integration.md)). MiniSearch is around **6 kB gzipped**, although size figures vary by source ([devpick](https://devpick.pages.dev/fuse.js-vs-minisearch)). Fuse.js is a reasonable alternative: one team chose it over Orama because Fuse needs no pre-indexing, while Orama spent 30-100 ms indexing at load and handled typos worse ([Liam ADR](https://liambx.com/docs/contributing/adr/20250205-use-fuse-js)). For charts, **Observable Plot (~83-92 KiB)** is the lightest capable option. **ECharts (~153-173 KiB)** has the richest built-in interactivity, including treemap drill-down. These figures come from a competing vendor's benchmark and should be treated as indicative ([TanStack](https://tanstack.com/charts/latest/docs/comparison)). For the table view, **Tabulator** (MIT, vanilla JS) provides header filters and CSV download with no build step. Grid.js is a ~15 KB lighter option. AG Grid locks Excel export behind its paid Enterprise tier ([wpdatatables](https://wpdatatables.com/javascript-table-library); [rv-grid](https://rv-grid.com/blog/best-js-datagrid-in-2026)).

There are two sensible architectures. The first keeps the current single `index.html`, uses Alpine.js and CDN libraries, and adds a GitHub Actions job that runs on push and on a weekly cron. That job validates the JSON, precomputes chart aggregates, geocodes HQs once, and writes `feed.xml`. The second moves to **Astro**, which generates per-company pages with `getStaticPaths` and build-time OG cards via Satori plus resvg, giving SEO and nicer link previews ([dev.to](https://dev.to/morellodev/generating-og-images-at-build-time-with-satori-and-astro-4b4b)). Pagefind can then add site-wide search with filter counts ([Pagefind](https://pagefind.app/docs/js-api-filtering/)). Adopting landscape2 directly gives the most "landscape" for the least code, but it means adopting its YAML format and UI, and customizing it means forking Rust and SolidJS code ([landscape2](https://github.com/cncf/landscape2)). Observable Framework is strong for dashboards, but its long-term direction is less certain since Observable Cloud was deprecated in April 2025 ([release note](https://observablehq.com/release-notes/2025-04-15-deprecating-observable-cloud)). The mapping advice (Leaflet with clustering, or a tile-free Plot/d3-geo dot map) comes from general knowledge, not sourced research. At any scale, the real performance costs will be logos and DOM rendering, not search. Lazy-load logos, and paginate card grids beyond a few hundred items.

## Conclusion

The best design choice is not visual polish but **choosing the two facets VC maps ignore, customer type and project phase, as first-class axes**. Once they drive both the filters and the heatmaps, the site stops being a list of logos. It becomes a gap-finder: an empty cell in "Operations x Owner" is a market signal that no static map can show. The multi-label schema, which looks like a complication, is what makes UpSet and phase swimlanes possible, and it rules out the treemaps that most market maps default to.

The suggested order follows from that. Ship the URL-stateful filter wall, detail drawer and open CSV first. Then add the two heatmaps and the weekly changelog/RSS. Add UpSet, the funding beeswarm and PNG export once funding text is parsed into structured fields. Move to per-company Astro pages only when search traffic justifies them. Two uncertainties remain: no commercial directory (Crunchbase, Dealroom) could be inspected for comparison or detail-page patterns, and no Lighthouse figures exist for a comparable site.
